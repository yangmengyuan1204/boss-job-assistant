4. 页面类型识别逻辑

采用 URL + DOM 双源识别，输出 PageTypeDetection(page_type, confidence, evidence, warnings)。

4.1 PageType 枚举

HOME / LOGIN / VERIFICATION / SEARCH_LIST / JOB_DETAIL / EMPTY_RESULTS / ERROR / UNKNOWN

4.2 识别规则

  • URL 路径匹配：基于 path 模式匹配（如 /web/geek/job → SEARCH_LIST），置信度 0.6
  • DOM 结构匹配：基于页面级选择器命中数量，置信度 0.5~0.8
  • 多类型冲突：多个类型同时命中时保守返回 UNKNOWN
  • 不根据 Cookie 判断登录态；不把"没有登录按钮"等价为"已登录"

每个卡片独立解析，保留 source_index，缺失字段为 None，空列表使用 default_factory=list。

7. 选择器候选机制

使用 @dataclass(frozen=True) SelectorCandidate(name, selectors, required, multiple) 集中管理。

  • 分层：页面级（PAGE_LEVEL_SELECTORS）→ 卡片级（LIST_CARD_ROOT / DETAIL_ROOT）→ 字段级（LIST_CARD_FIELD_SELECTORS / DETAIL_FIELD_SELECTORS）
  • 多候选回退：每个字段允许 tuple[str, ...] 多个选择器，按优先级尝试
  • 版本标识：SELECTOR_VERSION = "p2-v1"，写入 fixture 元数据
  • 禁止散落：所有选择器集中在 parsers/selectors.py

8. fixture 脱敏规则

8.1 必须删除的标签

script / style / noscript / iframe / svg / canvas / link / meta / base
embed / object / template / form / input / button / textarea / select / option

8.2 属性白名单

class / id / href / title / aria-label / role / alt

data-* 属性逐项审核，含 token/session/security/trace/uid/encrypt/csrf/nonce/auth/secret/key/uuid/device 关键字的全部删除。

8.3 文本脱敏

模式替换为
中国大陆手机号（1[3-9]xxxxxxxxx）<REDACTED_PHONE>
邮箱<REDACTED_EMAIL>
身份证号（18位）<REDACTED_ID>
长 token（≥32 位十六进制）<REDACTED_TOKEN>

8.4 URL 脱敏

  • 相对 URL 转绝对 URL（urljoin）
  • 仅允许 HTTP/HTTPS 与 BOSS 直聘官方域名
  • 删除 query 与 fragment
  • fixture 内删除全部 query 和 fragment

8.5 二次扫描

fixture 保存后执行 scan_high_risk_content() 二次扫描；发现高风险内容（手机号/邮箱/身份证/token）则抛 ValueError 拒绝写入。

10. observe-page 操作流程

python -m boss_tool observe-page [--output-dir tests/fixtures/pages] [--label list_page_basic]
  1. 加载配置，校验 run_control 红线（require_user_confirm / allow_unattended / allow_background）
  2. 校验 home_url（仅 BOSS 白名单域名，HTTPS，无 query/fragment/userinfo/端口）
  3. 启动 P1 BrowserManager（可见浏览器，持久化用户目录）
  4. 用户手动完成登录、手动导航到目标页面
  5. 命令循环（非阻塞轮询）：
    • status：输出 session 状态、脱敏 URL、页面类型候选、是否允许保存 fixture
    • inspect：只读页面侦察（不点击/滚动/导航/刷新），输出诊断摘要
    • save-fixture：要求精确输入 SAVE 才保存；登录页/验证页/未知页禁止保存
    • confirm：记录用户确认（不代表程序判断登录成功）
    • quit：安全关闭
  6. 浏览器关闭或 Ctrl+C 触发安全退出

11. parse-fixture 操作流程

python -m boss_tool parse-fixture tests/fixtures/pages/list_page_basic.html [--json] [--diagnostics] [--page-type TYPE]
  • 不启动浏览器，不访问网络，不执行 JavaScript
  • 仅使用 BeautifulSoup + lxml 解析本地 HTML
  • 输出结构化卡片/详情数据与诊断信息
  • 支持 --json（JSON 输出）、--diagnostics（诊断摘要）、--page-type（强制指定类型）

12. 解析诊断结构

class ParseDiagnostics(BaseModel):
    page_type: PageType
    selector_version: str
    root_matches: dict[str, int]        # 页面/卡片级选择器命中数
    field_matches: dict[str, int]       # 字段级选择器命中数
    missing_required_fields: list[str]  # 缺失的必填字段
    ambiguous_fields: list[str]         # 多候选冲突字段
    warnings: list[str]
    parser_success: bool

解析器不只返回成功/失败，能说明：找到多少卡片、每个选择器命中多少、哪些字段缺失、哪些字段多匹配、是否建议人工复查 fixture。

20. 安全声明

永久合规红线（全部遵守）：
  • 只使用 Playwright 可见浏览器（headless=False），持久化用户目录
  • 用户手动登录、手动导航、手动处理验证码/滑块/短信
  • 不自动识别验证码、不自动拖动滑块、不读取短信验证码、不自动登录
  • 不导入/导出/读取/保存 Cookie，不读取 localStorage/sessionStorage
  • 不使用 stealth，不修改 navigator.webdriver，不修改浏览器指纹
  • 不使用代理池，不轮换 IP，不切换账号
  • 不调用未公开接口，不逆向请求签名
  • 不抓取聊天内容，不自动发消息，不自动申请岗位
  • 不后台运行，不无人值守运行
  • 发现验证码/登录失效/风控提示时：只停止、提示用户、等待处理，不自动绕过
fixture 脱敏保障：
  • 所有 fixture 经 sanitize_html 脱敏（标签删除 + 属性白名单 + 文本脱敏）
  • 二次扫描发现高风险内容时拒绝写入并报错
  • 元数据不保存完整 URL / query / fragment / 用户身份 / Cookie / profile 路径
  • URL 输出统一使用 redact_url 脱敏（仅保留 scheme://host/path）
声明：本工具仅减少不必要访问与程序失控风险，不能保证账号不受限制，不得用于规避平台检测。
