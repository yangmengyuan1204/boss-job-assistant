2. 浏览器模块职责说明

2.1 BrowserManager

核心管理类，负责 Playwright 生命周期的所有方面：

  • 初始化 Playwright：通过 PlaywrightFactory 协议注入，生产环境惰性导入 playwright.sync_api，测试环境注入 fake 对象
  • 启动持久化浏览器上下文：调用 chromium.launch_persistent_context(user_data_dir=..., headless=False, args=[])，不使用临时 context + 手动 Cookie
  • 创建或复用用户目录：validate_user_data_dir 校验安全性后 mkdir(parents=True, exist_ok=True)
  • 获取初始页面：优先复用持久化上下文自带的页面，否则 new_page()
  • 打开配置的首页：_goto_home 二次校验白名单后调用 page.goto(url, wait_until="domcontentloaded")
  • 检测浏览器/上下文关闭：通过 context.on("close", ...) 与 page.on("close", ...) 监听关闭事件，区分程序主动关闭与用户关闭
  • 安全关闭：_cleanup_resources 按 页面 → 上下文 → Playwright 顺序清理，每步用 contextlib.suppress(Exception) 包裹，确保任何环节失败不影响后续清理
  • 幂等 close：重复调用不报错，_closed_by_manager 标志区分关闭来源
  • 启动异常清理：任何异常路径均调用 _cleanup_resources 并 session.mark_failed

2.2 BrowserSession

会话状态模型（Pydantic BaseModel，extra="forbid" 阻止敏感字段注入）：

  • 字段：session_id、started_at、ended_at、state、user_confirmed、browser_closed_by_user、stop_reason、home_url、user_data_dir、last_known_url、error_message
  • 生命周期方法：mark_started、mark_waiting_for_user、mark_user_confirmed、mark_closing、mark_closed、mark_failed
  • 禁止字段：Cookie、localStorage、sessionStorage、验证码、手机号、密码、指纹信息（Pydantic forbid 拒绝）

2.3 异常体系

BrowserError (基类)
├── PlaywrightNotInstalledError      # playwright 包未安装
├── ChromiumNotInstalledError        # chromium 二进制未安装
├── InvalidUserDataDirError           # 用户目录不安全
├── BrowserAlreadyRunningError        # 重复 start 被拒绝
├── BrowserNotRunningError            # 未启动即调用 API
├── BrowserStartFailedError           # 启动失败
├── HomePageOpenFailedError           # 首页打开失败
└── BrowserClosedByUserError          # 用户主动关闭

3. 会话状态机说明

3.1 状态定义

状态含义是否终态
CREATED会话已创建，尚未启动否
STARTING正在启动 Playwright 与浏览器否
WAITING_FOR_USER浏览器已打开首页，等待用户手动登录否
USER_CONFIRMED用户输入 confirm，自述处理完成（不代表程序判断登录成功）否
CLOSING正在关闭资源否
CLOSED正常关闭完成是
FAILED启动或运行失败是

3.2 合法迁移图

CREATED ──┬──▶ STARTING ──┬──▶ WAITING_FOR_USER ──┬──▶ USER_CONFIRMED ──▶ CLOSING ──▶ CLOSED
          │              │                      │                                    ▲
          │              ├──▶ CLOSING ───────────┴────────────────────────────────┘
          │              └──▶ FAILED
          ├──▶ FAILED
          └──▶ CLOSED (未启动直接关闭)

3.3 关键约束

  • transition_to 校验迁移合法性，非法迁移抛 ValueError
  • 终态不可迁移
  • mark_closed 幂等（重复调用只更新字段，不抛异常）

4. 人工确认流程说明

4.1 CLI 命令

python -m boss_tool browser-login [--config-dir DIR] [--home-url URL]

4.2 流程

  1. 加载配置（--config-dir 覆盖默认 config/）
  2. 初始化日志（setup_logging）
  3. 校验运行控制红线：require_user_confirm=True、allow_unattended=False、allow_background=False、headless=False、single_context=True、single_account=True，任一不满足 exit code=2
  4. 解析 home_url：--home-url 优先，否则使用配置；host 必须在 {www.zhipin.com, zhipin.com} 白名单
  5. 初始化 BrowserManager，调用 start() 启动可见浏览器并打开首页
  6. 终端显示明确提示： 
    请在浏览器中手动完成登录、扫码或安全验证。
完成后回到终端输入 confirm。
输入 quit 可退出。
  7. 进入命令循环，只接受 confirm / quit / status：
命令行为
confirm设置 user_confirmed=True，状态迁移到 USER_CONFIRMED；不声称自动判断登录成功；会话保持，用户可继续操作或 quit
quit调用 manager.close(stop_reason=USER_ABORTED)，安全退出
status输出 session_id / state / user_confirmed / started_at / last_known_url 等
空输入不视为确认，重新提示
未知命令给出提示 [提示] 未知命令: xxx。仅接受 confirm / quit / status。，不退出

4.3 状态返回值

允许返回：user_confirmed
禁止返回：login_verified（P1 不实现登录状态判断，除非后续通过真实页面侦察建立可靠且公开可见的判断）

5. 安全退出流程说明

5.1 支持的停止来源

来源处理stop_reason
Ctrl+CKeyboardInterrupt 捕获 → manager.close(stop_reason=USER_ABORTED)user_aborted
用户输入 quit命令循环检测 → manager.closeuser_aborted
用户关闭浏览器窗口context "close" 事件 → browser_closed_by_user=True + mark_closedbrowser_closed
用户关闭唯一工作页面page "close" 事件 → 同上browser_closed
Playwright 上下文异常关闭事件触发 + mark_failedunknown_error
启动失败start() except 块 → mark_failed + _cleanup_resourcesunknown_error
页面打开失败_goto_home 抛 HomePageOpenFailedError → 清理unknown_error
程序异常顶层 try/except 捕获 → closeunknown_error

5.2 停止时的强制行为

  1. 更新会话状态（mark_closing → mark_closed/mark_failed）
  2. 写入 ended_at 结束时间
  3. 写入 stop_reason
  4. 安全关闭资源（页面 → 上下文 → Playwright，每步 suppress 异常）

5.3 禁止行为

  • 不自动重启
  • 不自动刷新页面
  • 不自动重新登录
  • 不切换账号
  • 不继续后续采集流程
  • 异常关闭后不自动再次调用 start()

5.4 浏览器关闭检测

通过 _closed_by_manager 标志区分：

  • 程序主动关闭：标志置 True 后再调用 close，事件处理器直接 return，不标记 browser_closed_by_user
  • 用户关闭：标志为 False，事件处理器标记 browser_closed_by_user=True 并结束会话
  • 页面单独关闭：page "close" 事件触发，不自动重新打开 BOSS 页面
  • context 意外断开：context "close" 事件触发，状态正确迁移

6. URL 与日志脱敏说明

6.1 URL 脱敏

redact_url(url) 函数：仅保留 scheme://host/path，去掉 query 和 fragment。

>>> redact_url("https://www.zhipin.com/job/123?token=secret#frag")
'https://www.zhipin.com/job/123'

>>> redact_url(None)
None

>>> redact_url("")
''

应用位置：

  • BrowserSession.last_known_url 存储（脱敏后）
  • 日志中的 URL 输出

6.2 日志允许记录

  • 会话 ID（session_id）
  • 启动时间
  • 用户目录的规范化绝对路径
  • 首页域名（仅 host，不含 query）
  • 用户确认事件
  • 退出原因（stop_reason）
  • 异常类型（type(e).__name__，不含异常消息体）

6.3 日志禁止记录

  • 完整 Cookie / Authorization 头
  • localStorage / sessionStorage 内容
  • 验证码内容
  • 手机号 / 密码
  • 页面完整 HTML
  • 页面截图
  • 用户聊天内容

6.4 异常信息脱敏

session.error_message 仅存储 "启动失败: {ExceptionType}" 形式，不包含异常消息体（可能含敏感值）。测试 test_error_message_does_not_contain_sensitive_values 验证此行为。

  1. black 命令在当前环境卡住：black 26.5.1 在 Windows + 该 Python 环境下 black --check . 持续挂起，无法获得退出码。 已用 ruff format --check 替代（配置一致，结果兼容）。用户在本机验证时可手动执行 black --check . 确认。
  2. 未实现登录状态自动判断：P1 阶段不实现"是否已登录"的程序化判断。 confirm 命令仅代表用户自述已处理完成，不代表程序验证登录成功。 返回 user_confirmed 而非 login_verified。后续阶段如需自动判断，必须通过真实页面侦察建立可靠且公开可见的判断。
  3. 仅打开首页：P1 阶段浏览器只打开 BOSS 直聘首页，不进行搜索、翻页、详情页访问、岗位解析、年龄/劳动强度判断、地图、评分、Excel 输出等任何后续流程。
  4. Playwright 与 Chromium 依赖：本阶段未自动安装 Playwright 或 Chromium 二进制。 若环境未安装，browser-login 命令会给出清晰错误提示 python -m playwright install chromium，不自动下载。
  5. 用户目录必须由用户在配置中显式指定：默认配置 config/runtime.yaml 中 browser.user_data_dir 指向项目内 ./user_data， 用户可改为其他安全路径，但必须通过 validate_user_data_dir 校验。
  6. 测试不访问真实网络：所有浏览器测试使用 tests/browser_fakes.py 中的 FakePlaywrightBundle，test_browser_tests_do_not_use_real_zhipin_network 测试验证此约束。
  7. 真实运行限制：允许用户手动执行一次 python -m boss_tool browser-login 验证浏览器打开、持久化目录、登录、confirm/quit、关闭等流程； Agent 不自动执行真实网站联机测试，真实测试必须由用户本人操作。
  8. 未实现 run_logs 持久化：本阶段 BrowserSession 仅在内存中维护， 未写入 SQLite run_logs 表（该表已在 P0 建立）。会话状态在程序退出后不保留。 后续 P2 阶段可补充持久化。
  9. migrations.py 覆盖率为 0%：P0.1 重构后 migrations.py 仅含占位代码（实际迁移逻辑在 database.py 中）， 计划在 P2 阶段补充独立迁移脚本与对应测试。

15. 安全声明

本工具的安全措施仅能：
  • 减少不必要的页面访问
  • 降低程序失控风险
  • 提供清晰的人工确认与紧急停止机制
  • 记录必要的运行状态用于审计
本工具的安全措施不能：
  • 保证账号不被平台限制
  • 规避平台检测或风控机制
  • 替代用户对自身账号安全的责任
用户使用本工具即表示理解并接受上述限制。
